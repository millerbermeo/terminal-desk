# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

> **Cosas que el usuario debe hacer a mano (subir `.odesk/project.json` a git, API en marcha, migraciones, copias, secretos): ver `OBLIGATORIO.md`. Menciónalo si tocas el enlace local o el servidor.**

**Odesk Agent** (antes «ODESK AI» y «Centro de Proyectos»; el icono está en `resources/`): app de escritorio (Electron + Vite + React + TypeScript) que gestiona proyectos con varias terminales reales (xterm.js + node-pty) y lanza CLIs de IA (hoy, Claude Code) dentro de ellas. Todo el código, los identificadores y la UI están en español; mantenlo así.

## Comandos

Usa **pnpm** (el repo tiene `pnpm-lock.yaml`; `pnpm-workspace.yaml` autoriza con `allowBuilds` los scripts de `electron` y `node-pty`).

```bash
pnpm install        # el postinstall recompila node-pty para Electron; si falla: pnpm exec electron-rebuild -f -w node-pty
pnpm dev            # electron-vite dev (HMR solo en el renderer)
pnpm build          # electron-vite build -> out/
pnpm typecheck      # tsc --noEmit
pnpm lint           # eslint (typescript-eslint corre sobre la API de TS 6 vía .pnpmfile.cjs; TS 7 aún no está soportado)
pnpm test           # vitest run (tests/ — LLM falso, git real en temporales, servidor MCP de prueba por stdio)
pnpm evals          # evals contra el modelo real (evals/; necesita ANTHROPIC_API_KEY, consume tokens; sin clave se omite)
ODESK_EVAL_CLI=1 pnpm evals -- asistente   # el Asistente de punta a punta con el CLI REAL (suscripción, Haiku): evals/asistente-{real,robustez,limites}.eval.ts sobre `evals/banco-asistente.ts` (HOME temporal, proyecto de prueba)
pnpm package        # build + electron-builder (node-pty va en asarUnpack)
```

- **Cambios en `src/main` o `src/preload` requieren reiniciar `pnpm dev` por completo**; el renderer se recarga solo (Ctrl+R).
- Si el entorno tiene `ELECTRON_RUN_AS_NODE=1` (p. ej. dentro de VSCode), Electron arranca como Node y falla con `Cannot read properties of undefined (reading 'commandLine')`: lanza con `env -u ELECTRON_RUN_AS_NODE pnpm dev`.
- Para probar la app real sin ver la ventana: lanzar `electron . --remote-debugging-port=9222` (con `HOME` apuntando a una carpeta temporal para no tocar `~/.odesk-agent`) y manejarla por CDP. Hay que enviar `Page.bringToFront` y `Emulation.setFocusEmulationEnabled` o los eventos de ratón tardan ~5 s cada uno. Los ptys se miden con `ps` (hijos del proceso principal).
- La lógica pura (`src/renderer/arbol.ts`, `src/shared/*`, y `src/main/*.ts` con un loader de alias para `@shared/*`) se puede probar con `node --experimental-strip-types`.

## Arquitectura

Tres procesos con un contrato IPC tipado. **Añadir una operación IPC toca siempre tres sitios**: `src/shared/ipc.ts` (canal en `Canales` + método en `ApiCentro`), `src/preload/index.ts` (implementa `ApiCentro` con `ipcRenderer`) y `registrarIpc()` en `src/main/index.ts`. El renderer solo ve `window.api`; `contextIsolation`, `sandbox` y CSP están activos, así que el preload solo puede importar `electron` y `@shared/*`. Alias `@shared` -> `src/shared` (configurado en `electron.vite.config.ts` y `tsconfig.json`).

### Terminales y ventanas (lo menos obvio)
- `GestorTerminales` (`src/main/terminales.ts`) es dueño de los ptys y guarda un historial por terminal (512 KB) con un contador acumulado `fin`. Cada trozo de salida viaja con su `fin`.
- `duenos` (`src/main/index.ts`) mapea `ptyId -> webContents.id`: la salida va solo a la ventana dueña. Al recargar o cerrar una ventana (`cerrarDe`) se matan sus ptys; cerrar la ventana principal cierra toda la app.
- **Separar/devolver pestañas** reutiliza los mismos procesos: `ventana:separar` abre una `BrowserWindow` con `?ventana=<token>` (renderer `VentanaSeparada`, que recoge el payload con `ventana:tomar`); `ventana:devolver` reasigna los ptys a la principal y cierra la separada. El panel receptor usa `terminal:adjuntar`, repinta el historial y descarta los trozos en cola con `fin <= histórico` (evita duplicados). En el emisor, `transferidas` (`TerminalPanel.tsx`) evita que desmontar el panel mate el pty.
- Un proveedor de IA no se lanza con `spawn` directo: su comando se **escribe en el shell interactivo** (hereda PATH/nvm; al salir del CLI la terminal sigue viva). El renderer solo manda `proveedorId`; el comando se resuelve en main.
- Las terminales de la UI tienen dos ids: `TerminalInfo.id` (renderer) y `ptyId` (proceso real, lo informa `TerminalPanel` con `onPty`).

### Renderer
- `App.tsx` mantiene `ventanas` (pestañas, normalmente una por grupo; id = id del grupo, `__sin-grupo__` o `__libre__`). **Todas las pestañas y la vista principal permanecen montadas** (`display: none`) para no matar los ptys: nunca desmontes condicionalmente `TerminalPanel`/`TerminalGrid`. Un clic en un proyecto enfoca su terminal si ya existe (`proyectoId`); duplicar solo es posible a propósito (✦ con proveedor, «+ Terminal»).
- `TerminalGrid` pinta un **árbol de divisiones** (`arbol.ts`, funciones puras): siempre cubre el área sin huecos; cada divisor mueve una línea completa; mover una terminal = intercambiar hojas. El árbol guardado conserva las proporciones y `normalizar()` aplica los mínimos (260×150 px) solo al dibujar. `reconciliar()` ajusta el árbol al abrir/cerrar terminales. Los ajustes de tamaño de xterm se limitan a uno cada 50 ms.

### Servidor (proyectos y agentes)
Proyectos, grupos y la biblioteca de agentes/skills **ya no están en JSON local**: viven en el backend `../terminal-desk-api` (NestJS + Drizzle + Postgres, repo aparte; ver su README). `src/main/servidor/cliente.ts` (`servidor`) es el único cliente HTTP: guarda el JWT cifrado con `safeStorage` (`sesion.json`; sin llavero seguro solo en memoria), lo envía en cada petición y lanza `ErrorSesion` si falta o venció. Dirección del servidor, de mayor a menor prioridad: `ODESK_API_URL`, lo guardado en `servidor.json` (botón «cambiar» del acceso) y la de por defecto: `URL_SERVIDOR_PRODUCCION` (`https://odesk.millerrivera.com`, `shared/sesion.ts`) en la app instalada o `http://localhost:3000` en desarrollo. «Instalada» = empaquetada (`app.isPackaged`), o una copia hecha con `install.sh`/`install.ps1`, que dejan `servidor-por-defecto.txt` junto a `repo/` (el lanzador no es una app empaquetada; `main/servidor/por-defecto.ts#servidorPorDefecto`, también vale `ODESK_SERVIDOR_POR_DEFECTO`). `proyectos.ts#leerProyectos` y `agentes.ts#leerBiblioteca` mantienen su firma pero leen del servidor (caché de 2 s, `olvidarProyectos()` tras cada cambio). Los ids de proyecto/grupo/recurso son ahora UUID del servidor. La ventana principal muestra `components/Acceso.tsx` hasta que hay sesión (`Raiz` en `renderer/main.tsx`); al iniciar sesión, `servidor/importar.ts` sube los proyectos del antiguo `proyectos.json` si la cuenta está vacía. Los tests que usan `Nucleo` levantan `tests/servidor-falso.ts` (`ServidorFalso`: `apuntar()` antes de importar, `entrar()` después).

**Enlace local y contexto compartido entre equipos**: el servidor no guarda rutas (tabla `projects`: nombre, `repo`, grupo). `servidor/vinculo.ts` escribe `<carpeta>/.odesk/project.json` (solo `{projectId}`, pensado para subirse a git) y `servidor/rutas.ts` (`rutas.json`, local) guarda dónde está cada proyecto **en este equipo**; `leerProyectos` solo devuelve los de la cuenta que tienen carpeta aquí. `agregarProyectos` → `resolverProyecto`: si la carpeta trae `.odesk/project.json` de un proyecto de la cuenta lo **reanuda** (mismo id, `reanudados` en el resultado → `Nucleo.hidratar` baja tablero, conversaciones y trazas; si no trae el archivo, busca en la cuenta el único proyecto con el mismo remoto de git (`proyectoPorRepo`/`claveRepo`: `propietario/repo`, sin importar https, ssh o alias) que aún no tenga carpeta aquí y lo reanuda escribiendo el enlace (con varios candidatos, o ya enlazado, no adivina); si tampoco, registra uno nuevo y escribe el archivo. «Quitar» un proyecto solo lo suelta de este equipo. `servidor/sincronizador.ts` sube en segundo plano (agrupa 1,5 s, reintenta, nunca bloquea) lo que cambia: `AlmacenJson` acepta un 3.º argumento `alGuardar(id, nuevo, previo)` que usan tareas, sesiones y trazas; `Nucleo.registrarArchivoTocado` anota como eventos los archivos que toca la IA. Resolución de conflictos: gana el `updatedAt`/`actualizada` más reciente (`ServicioTareas.fusionar`, `MemoriaCortoPlazo.fusionar`, `AlmacenTrazas.fusionar`). Los borrados de conversaciones/trazas no se propagan. Solo se sincronizan ids de proyecto que son UUID del servidor.

**Cuentas y seguridad (escritorio)**: el acceso (`components/Acceso.tsx`) tiene los pasos entrar · crear cuenta → código del correo · olvido → código + nueva contraseña; el panel `components/Cuenta.tsx` cambia la contraseña y cierra sesión (aquí o en todos los equipos). Las operaciones van por un canal tipado `sesion:cuenta` (`OperacionesCuenta` en `shared/sesion.ts`). `ClienteServidor` revoca la sesión en el servidor al cerrar (`/auth/logout`), y **se niega a mandar nada por http a otra máquina** (`servidorSeguro`; `ODESK_PERMITIR_HTTP=1` solo para pruebas). **Datos locales por cuenta**: `src/main/perfiles.ts#cambiarPerfil` se llama tras cada login (`conSesion` en `index.ts`); si la cuenta es otra, aparta lo personal de `~/.odesk-agent` a `perfiles/<id>/`, recupera lo de la nueva, limpia el almacenamiento del navegador integrado y de la interfaz, y **reinicia la app** (`app.relaunch`). Lo compartido está en `COMPARTIDOS` (token, servidor, worktrees, plugins generados, socket); todo lo nuevo que se guarde en la carpeta de datos es personal por defecto. Prueba real: `API_LOG=/tmp/api.log pnpm e2e:equipos` (API sin SMTP con su salida en ese archivo; lee de ahí los códigos).

**Datos de cuenta en la nube**: `servidor/sync-cuenta.ts` (`SincronizadorCuenta` con fuentes `FuenteArchivos` —memoria, permisos, preferencias, `ajustes/<proyecto|global>.json` (modelo y autonomía del Asistente: `main/ajustes.ts`, canal `ajustes:leer/fijar`; «autónomo» no se sube y no pisa lo local), proveedores y `mcp.json`, estos dos sin `env`— y `FuenteTareas` —tareas sin proyecto y columnas—) compara cada documento con lo último sincronizado (`sync-cuenta.json`: hash + updatedAt + cursor) contra `/me/docs`; la primera vez de un equipo manda el servidor. `servidor/boveda.ts` + `servidor/secretos.ts`: bóveda E2E (scrypt + AES-256-GCM, la clave local cifrada con `safeStorage` en `boveda-clave.json`) con las secciones `proveedores`, `mcp` (por nombre: se suman), `api` y `github`; concurrencia optimista con `base` (409 → reintenta). Bucle de 30 s en `index.ts` (`sincronizarCuenta`: cuenta → bóveda → `nucleo.sync.vaciar()` → `nucleo.hidratarTodos(true)` incremental con `?since=` cursor del servidor). Borrados hechos por el usuario (`Nucleo.borrarSesion`, `eliminarTraza`, tareas) dejan marca en el servidor (`deleted`); la poda automática no se propaga.

### Persistencia (`~/.odesk-agent/`)
Antes era `~/.centro-proyectos/`: `src/main/migracion.ts` la mueve sola al arrancar (se ejecuta al evaluar `proyectos.ts`, antes de que nada lea `DIR`; renombra, y si no puede copia y borra el origen solo si la copia terminó; si falla se sigue usando la antigua para no parecer «vacía»). Tras mover, `core/git/reparar.ts` rehace con `git worktree repair` los worktrees de agentes (guardan rutas absolutas). El perfil de Electron (`userData`) también se mueve (`resolverPerfil`).
`proveedores.json` (0600; `env` en texto plano) y `sesiones/`; tareas, memoria, etc. siguen locales. `proyectos.json` y `agentes.json` quedaron como legado: ya no se escriben. Los módulos de `src/main` serializan sus escrituras con una cola `enCola`.

### Agentes y skills de Claude Code
Biblioteca de recursos (compartidos o individuales de un proyecto) con activación por grupo/proyecto (`src/shared/agentes.ts#activosDe`, usado por main y renderer). Al crear una terminal con un proveedor cuyo binario es `claude` y con `proyectoId`, `comandoConAgentes` (`src/main/agentes.ts`) genera un plugin de Claude Code en `sesiones/<proyecto>-<hash>/` (carpeta inmutable por contenido) y añade `--plugin-dir`. Una terminal normal o un `claude` escrito a mano no los carga. Nada se escribe en el repo del proyecto. **En el Asistente** (`pluginAgentesAsistente`): `Agent` (+1,2 k tokens por llamada) solo si hay agentes y `Skill` (+0,8 k) solo si hay skills, contando también los `.claude/agents|skills` del repo (`recursosDeCarpeta`); `CLAUDE_CODE_DISABLE_BUNDLED_SKILLS=1` quita las skills del propio CLI (costaban +2,5 k en cada llamada). Con recursos, `avisos.ts#guiaRecursos` añade al prompt de sistema el criterio de cuándo delegar o cargar una skill (sin él, el modelo hacía él mismo lo que era especialidad de un agente). Eval con el CLI real y los mismos argumentos: `ODESK_EVAL_CLI=1 pnpm exec vitest run --silent=false --config vitest.evals.config.mts evals/agentes-cli.eval.ts` (implícito/explícito/trivial/casi; consume suscripción).

**Caveman (global)**: `src/main/caveman.ts` mantiene el plugin de Claude Code [Caveman](https://github.com/JuliusBrussee/caveman) (respuestas comprimidas, ~75 % menos tokens) en `~/.odesk-agent/caveman/v-<sha>/` (compartido entre cuentas: está en `COMPARTIDOS`). `GestorCaveman.actualizar()` consulta `git ls-remote` y, si hay commit nuevo, clona `--depth 1` en un temporal, quita `.git` y lo renombra a `v-<sha>` (inmutable; se conservan 2 versiones para sesiones en marcha); `actual.json` apunta a la vigente. Se lanza al arrancar y cada 6 h (`mantenerCavemanActualizado`, nunca bloquea ni lanza); la primera vez siembra con el Caveman que ya tenga instalado `claude plugin install` (`installed_plugins.json`) mientras clona. `pluginCaveman()` da la carpeta y se añade como `--plugin-dir` extra en **toda** terminal de Claude Code (`comandoConAgentes`, con o sin proyecto) y en el Asistente (`pluginDirs` de `suscripcion.ts`); al ir por `--plugin-dir` funciona con cualquier cuenta/`CLAUDE_CONFIG_DIR` sin tocar su `~/.claude`. Sus ganchos necesitan `node` en el PATH. `ODESK_SIN_CAVEMAN=1` lo apaga. Modo por defecto «full» (cambiar con `/caveman lite|full|ultra` o `CAVEMAN_DEFAULT_MODE`). **Versión ligera**: el plugin entero trae 22 skills y 3 agentes que el CLI describe en cada turno (~3.800 tokens); `GestorCaveman.rutaPluginLigero()` deriva `ligero-<sha>/` (solo ganchos SessionStart/UserPromptSubmit, `src/hooks/` y `skills/caveman`) y es el que se usa en el Asistente y en las terminales (`pluginCavemanLigero`). Las terminales no lo añaden si `settings.json` de la cuenta ya activa Caveman (`cavemanEnAjustes`: ganchos o plugin), para no ejecutar sus ganchos dos veces. **Asistente aislado**: `claude -p` va con `--setting-sources project,local --strict-mcp-config` (sin skills/plugins/conectores del `~/.claude`) y con `--disallowedTools Agent(Explore) Agent(general-purpose) …` (`SUBAGENTES_INTEGRADOS`): solo delega en los agentes del proyecto. El consumo real por modelo (`modelUsage` del resultado) se anota en el `Medidor` (`alUso`).

## Notas
- `src/main/core/` = núcleo de agentes propio, hablado directamente con la API de Anthropic (no envuelve un CLI). **No confundir** con `src/main/agentes.ts` (biblioteca de plugins para Claude Code). Dos proveedores (`preferencias.json`, por defecto **suscripción**): `suscripcion.ts` ejecuta `claude -p --output-format stream-json` y traduce su salida a `EventoAgente` (sesión con `claude auth login`, `ANTHROPIC_API_KEY` se elimina del entorno del hijo; flujos y grupos no disponibles); `api` usa el núcleo propio y necesita `ANTHROPIC_API_KEY` (entorno o `env` del proveedor `claude`). Los tests que usan `LlmFalso` deben fijar `await nucleo.preferencias.fijar('api')`. Documentado por fases en `docs/`:
  - `fase-1.md`: agente, bucle, harness, subagentes, registro de herramientas, cliente MCP.
  - `fase-2.md`: monitor de contexto (poda/resumen automático), memoria corta (`conversaciones/`) y larga (`memoria/`).
  - `fase-3.md`: grafo de estados (`modo: 'flujo'`), router de modelos, A2A por `grupoId`.
  - `fase-4.md`: flujos en git worktrees (`worktrees/`), guardrails (credenciales, rutas, destructivo) y confirmación humana (`solicitud_humana` + `core.responder`).
  - `interfaz.md`: editor de archivos de cada celda (`src/main/archivos.ts` confinado al proyecto, `src/renderer/editor/` con CodeMirror 6) y pestaña **Asistente** del renderer (`components/Asistente.tsx`, estado en `agente/useAgente.ts`, alojado en `App`): conversación con streaming, trazas, memoria, ramas, evals y el modal de confirmaciones.
  - `permisos-autonomia-comandos.md`: reglas de permisos persistentes (`permisos/`), modos de autonomía (Preguntar/Ediciones/Autónomo, presupuesto de tokens) y comandos propios con `/`, que viven en el servidor (tabla `commands`, `/comandos`; `core/comandos/store.ts` es su cliente, globales o por UUID de proyecto; los JSON antiguos de `comandos/` se suben una vez y quedan como `.migrado`).
  - `fase-5.md`: trazas (`trazas/`, spans con AsyncLocalStorage, credenciales redactadas) y evals (`evals/`, aserciones + juez LLM + comparación de informes).
- **Control del consumo de tokens** (`core/consumo.ts`, `core/rotacion.ts`, `main/guardia.ts`, `docs/consumo.md`): el CLI reenvía todo el contexto en cada llamada, así que se acota como lo hace Claude Code. `entornoSuscripcion` fija `CLAUDE_CODE_AUTO_COMPACT_WINDOW=200000` + `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE=70` (compacta a ~140 k aunque el modelo tenga 1 M; las terminales ✦ lo reciben como prefijo de entorno en Linux/macOS) y recorta salidas de Bash/MCP. Como respaldo, `ejecutarPorSuscripcion` consulta `MetaSesionesCli` (`sesiones-cli-meta.json`: contexto, imágenes, acumulado) y, si `decidirRotacion` lo pide (contexto ≥ 170 k, ≥ 10 imágenes o caché caducada con mucho contexto), `prepararRotacion` resume la transcripción con Haiku (`consultarCli`, sin herramientas) y la ejecución sigue en una sesión nueva con el resumen en el primer mensaje (`prefijoPrompt`; el usuario ve su `prompt` intacto y una nota `contexto_compactado`). **`modelUsage` del CLI es acumulado de la sesión reanudada**: `diferenciaUso` resta el acumulado previo antes de anotar en el `Medidor`; no lo anotes tal cual. Las trazas de suscripción reciben su consumo con `Trazador.anotarUso` y se cierran con su estado real (`finalizar(id, estado)`; sin spans de agente caía a `error`). Plugin `odesk-guardia` (`pluginGuardia()`, en `sesiones/guardia-<hash>/`, también en terminales ✦): gancho `PreToolUse` sobre `Read` que reduce y limita las imágenes. Tope por ejecución `--max-budget-usd` (`ODESK_PRESUPUESTO_TURNO_USD`, 5). Ajustes y variables en `docs/consumo.md`.
- **Dictado por voz** (`renderer/agente/grabadora.ts` → `Grabadora`, `components/GrabadorVoz.tsx`, `main/voz.ts` → `ServicioVoz`, `shared/voz.ts`, canales `voz:estado`/`voz:transcribir`; backend `src/voz/` de `terminal-desk-api`): 🎤 del chat comprueba `/voz/estado` **antes** de abrir el micrófono, graba Opus mono 24 kbps (máx. 3 min, se para sola), y al terminar manda **una** petición binaria (`ClienteServidor.binario`, cabecera `x-duracion-ms`) a `/voz/transcribir`: Groq `whisper-large-v3-turbo` en español y, solo si `necesitaMejora`, una corrección con el primer modelo activo de `GROQ_MODELO_TEXTO` → `MODELOS_TEXTO` (hoy `openai/gpt-oss-20b`, con `reasoning_effort: low`; Groq retira modelos: `llama-3.1-8b-instant` ya no existe, y la lista sale de la validación de la clave), descartada si `mejoraAceptable` falla. El texto se inserta en el cursor y **nunca se envía solo**; «Usar lo que dije» vuelve a la transcripción literal. `GROQ_API_KEY` vive solo en el `.env` del backend. Los errores viajan como datos `{ok:false, codigo}` (por IPC un `throw` pierde el código). Ver `OBLIGATORIO.md` §11.
- **Uso del plan de suscripción** (`core/uso/plan.ts`, `Medidor.fijarPlan`, chip «5 h · sem» de `BarraUso`): `GET https://api.anthropic.com/api/oauth/usage` (el mismo que `/usage` de Claude Code; `anthropic-beta: oauth-2025-04-20`) con el `accessToken` de `<carpeta de la cuenta activa>/.credentials.json`; solo lectura, no renueva la sesión ni guarda el token. Cada 60 s con alguna ventana visible y 4 s después de cada mensaje (`planPronto`); un 429 pausa 5 min; un fallo conserva los últimos datos. En macOS la sesión está en el llavero: no hay dato. Endpoint no documentado: si cambia, `interpretarUsoPlan` devuelve vacío y solo falta el chip.
- **Proceso persistente del CLI** (`core/proceso-cli.ts`, `suscripcion.ts#LectorTurno/CanalControl/argumentosCli`): como la extensión de VS Code (SDK de agentes), un solo `claude` con entrada stream-json atiende todos los mensajes de una conversación (`ProcesosCli`, máx. 4 vivos, 20 min de inactividad, `ODESK_PROCESO_POR_TURNO=1` para volver a uno por mensaje). `LectorTurno` traduce el stream de UN turno (lo comparten ambos modos); `CanalControl` envía peticiones de control al CLI: `interrupt` (cancelar sin matar), `side_question` («Preguntar ahora», con contexto real), `get_context_usage` (`Nucleo.contextoUso` → `BarraUso`) y `rewind_files` (`rebobinarArchivos` → botón «↩ Deshacer cambios»; necesita `CLAUDE_CODE_ENABLE_SDK_FILE_CHECKPOINTING`, que `entornoEjecucion` activa, y el `mensajeId` que se manda como `uuid` y viaja en el evento `inicio`). **El prompt de sistema de un proceso persistente tiene que ser estable** (cambiarlo relanza el proceso y, en la API, invalida la caché de toda la conversación): `Nucleo.contextoPartes` deja en `--append-system-prompt` solo lo estable y manda lo variable (memoria, tareas, estado de git) delante del mensaje, y solo si su huella cambió (`MetaSesionCli.hashDinamico`). Un cambio de modelo, autonomía, plugins, MCP, carpetas o cuenta lanza otro proceso y reanuda la sesión (`firmaProceso`). `--tools` limita las herramientas del CLI (`herramientasCli`): contexto base 11,4 k en vez de 24,7 k. **`ToolSearch` tiene que estar en esa lista**: sin ella el CLI no puede diferir las herramientas MCP y manda enteras las 67 del servidor «odesk» (+17 k tokens por llamada, medido); con ella solo sus nombres, y el modelo carga el esquema al usarlas. Los tests con un `claude` falso de un solo mensaje deben fijar `ODESK_PROCESO_POR_TURNO=1`. **Turnos y eco**: el CLI **ignora en silencio** un mensaje con un `uuid` ya visto (ni salida ni error), así que cada envío lleva uno nuevo (solo el primero de un turno lleva el `mensajeId` para deshacer; las continuaciones automáticas y los cambios de cuenta usan otro). El proceso va con `--replay-user-messages` y `LectorTurno` (`esperarEco`) descarta todo lo anterior al eco de su mensaje; si el eco no llega en `ODESK_ESPERA_ECO_S` (120 s) se mata el proceso y el turno termina con error. Las tareas en segundo plano del CLI se apagan (`CLAUDE_CODE_DISABLE_BACKGROUND_TASKS`, `ODESK_TAREAS_FONDO=1` las permite): al acabar una, el CLI abría solo un turno sin mensaje del usuario que desordenaba los siguientes. Pasar el tope de pasos interrumpe y, si en 10 s no hay resultado, mata el proceso.
- **Preguntas laterales («Preguntar ahora»)** (`ChatAgente.tsx`, `useAgente.preguntarAhora`, IPC `core:lateral` → `Nucleo.preguntarLateral`, `core/bitacora.ts`): con una tarea de suscripción en marcha, además de «Encolar» (espera a que termine) el botón **Preguntar ahora** responde ya **sin cancelar ni esperar** la tarea. Cada ejecución por suscripción lleva una `Bitacora` (petición, textos, herramientas y resultados, acotada a ~12 KB) alimentada por `emitir`; la pregunta lanza otro `claude -p` (`MODELO_LATERAL` = `haiku`, solo lectura, autonomía «preguntar») con esa bitácora en `--append-system-prompt`. **No** usa `--resume --fork-session`: probado, el fork retoma la tarea pendiente (tarda ~90 s y reintenta escribir). El turno lateral (`Turno.lateral`) tiene su propio `ejecucionId`, no cuenta en `enCurso` ni decide si avanza la cola, y se guarda en la transcripción. Solo suscripción: sin tarea viva o en modo API falla y la pregunta se encola como mensaje normal.
- **Una ejecución a la vez por conversación** (suscripción): `Nucleo.turnosSesion` encola en el núcleo un mensaje que llega con otro en marcha (`esperarTurnoAnterior`; cancelarlo mientras espera no envía nada). Sin esto, un mensaje con otra configuración (autonomía, modelo) cerraba el proceso persistente con la tarea a medias. La interfaz además encola por su lado («Encolar»).
- **Modo «Autónomo» sin confirmaciones pero con red**: `Bash` no va en `--allowedTools`; cada comando pasa por `crearPermisoCli` (con `autonomia`), que lo aprueba al instante salvo lo catastrófico (`core/guardrails/autonomo.ts#motivoBloqueoAutonomo`: sudo/su, borrar raíz/HOME/sistema, push forzado en cualquier orden, discos, apagar, `curl|sh`… en cadenas, subshells y `bash -c`), que deniega con evento `guardrail`. Las terminales ✦ de grupo (que permiten `Bash` de golpe) llevan `ODESK_GUARDIA_AUTONOMA=1` y el plugin del proyecto un gancho `PreToolUse` de Bash (`mcp-tareas.js hook-bash`) con la misma regla; sin esa variable el gancho no bloquea nada (hay una persona aprobando).
- **Varias cuentas de suscripción** (`src/main/core/cuentas.ts`, `cuentas.json` + `cuentas/<id>/`): la principal es el `~/.claude` de siempre; las demás usan `CLAUDE_CONFIG_DIR` y guardan su propio login. La cuenta activa se elige a mano; con «cambiar sola», un `rate_limit_event` rechazado (o 429/texto de límite) en `ejecutarSuscripcion` hace que `ejecutarPorSuscripcion` (`core/index.ts`) reintente con otra cuenta con sesión. Si aún no ejecutó herramientas se repite el mensaje; si se cortó **a mitad de la tarea**, se guarda la sesión del CLI de ese turno (su transcripción ya tiene lo hecho) y la otra cuenta la reanuda con `PROMPT_SEGUIR_OTRA_CUENTA` («continúa donde quedaste, no repitas»), sin resumen, para no duplicar cambios (`cuenta_cambiada.continua`). Sin otra cuenta disponible, esa sesión a medias también queda guardada para el siguiente mensaje. La conversación se lleva copiando su `projects/*/<sesión>.jsonl` (`llevarSesion`), sin reenviar historial. No se guarda el id de sesión de una ejecución rechazada.
- **Tareas** (`src/main/core/tareas/`, `src/shared/tareas.ts`, pantalla `components/Tareas.tsx`): `ServicioTareas` es el único que escribe `tareas/tareas.json`; las reglas (terminar exige criterios/subtareas/dependencias, motivo al bloquear/descartar/reabrir, sin ciclos) son funciones puras compartidas. La interfaz usa un solo canal IPC (`tareas:operar`, autor «usuario»); la IA usa las herramientas de `shared/tareas-herramientas.ts` (autor «ia»): por el registro del núcleo en modo API, y por un **servidor MCP** (`src/main/mcp-tareas.ts`, segundo entry de `electron.vite.config.ts`, lanzado con `ELECTRON_RUN_AS_NODE=1`) en suscripción (`--mcp-config`) y en las terminales ✦ (`.mcp.json` del plugin). El MCP no tiene datos: llama por un socket local (`tareas.sock` + `tareas.token`) al proceso principal. La IA no puede borrar tareas. Ver `docs/tareas.md`.
- **Control de versiones (git)** (`src/main/core/git/`, `src/shared/versiones.ts`, pantalla `components/Versiones.tsx`): un solo canal IPC `git:operar` (`OperacionesGit`) con el **id del proyecto** (main resuelve la carpeta; el renderer nunca manda rutas de repo). `repositorio.ts` ejecuta git con `execFile`, rutas tras `--` y `GIT_LITERAL_PATHSPECS=1` (opt-in en `git()`; `stash -u` necesita desactivarlo), desde la raíz del repo, con las escrituras en cola por repositorio. `analisis.ts` analiza `status --porcelain=v2`, `log`, `for-each-ref` y traduce errores. Sin push forzado ni reset duro. Ver `docs/versiones.md`.
- **Navegador integrado y cliente API**: `src/main/navegador.ts` (ventana con la barra de direcciones de la app, `?navegador=<id>`, más una `WebContentsView` aislada: sandbox, sin preload, sesión `persist:navegador`, solo http/https, permisos denegados; `session` se configura al abrir la primera ventana porque antes de `ready` no existe) y `src/main/puertos.ts` (detección de servidores locales). Cliente API: `src/main/api/` (ejecutor `http`/`https` con redirecciones, compresión, límite y cancelación; `servicio.ts` guarda colecciones/entornos/historial en `api/datos.json` 0600) y un canal `api:operar` tipado (`OperacionesApi`); la lógica pura (variables, cURL, `normalizarUrl`) está en `src/shared/api.ts` y `navegador.ts`. Ver `docs/navegador-api.md`. **La IA maneja el navegador integrado** con las herramientas `navegador_*` del MCP `odesk` (`shared/navegador-herramientas.ts`; `main/navegador-ia.ts` usa `webContents.debugger` sin puerto y foco simulado para varias ventanas a la vez; `main/navegador-pagina.ts` corre en un mundo aislado: instantánea con refs y marca visual). Playwright MCP de serie va con ventana y `--isolated`.
- **Móviles Android por USB (adb)**: herramientas `movil_*` del MCP `odesk` (`shared/movil-herramientas.ts`, lógica pura en `shared/movil.ts`, ejecución en `main/movil.ts` → `MovilIA`, conectado con `nucleo.conectarMovil`): instantánea de `uiautomator dump` con refs, toques/texto/teclas con `input`, apps, instalar APK, logcat y evidencias en `evidencias/movil/`. Sin herramientas que borren (ni `pm clear`/`uninstall` por `movil_shell`) ni elevar privilegios; la autorización de depuración la da la persona en el teléfono. Ver `docs/movil.md`.
- **GitHub y herramientas de git/GitHub para la IA**: `src/main/github/` (cliente REST con errores traducidos, `AlmacenToken` con `safeStorage`: nunca en claro, `servicio.ts`, `askpass.ts`) y un canal `github:operar` (`OperacionesGitHub`). Sin el CLI `gh` (no hace falta instalarlo): API REST + token; el repositorio se deduce del remoto, resolviendo alias SSH con `ssh -G` (`ssh.github.com` = GitHub). A git se le dan credenciales por `GIT_ASKPASS` solo para https del servidor de GitHub (`Repositorio` recibe un `ProveedorCredenciales`). **Un único servidor MCP `odesk`** (`shared/herramientas-odesk.ts`) con tareas + git + GitHub; `core/herramientas-odesk.ts` es el ejecutor común (registro del núcleo en modo API y socket/MCP). `permisosCli`: lectura siempre, escritura desde «ediciones», `ejecucion` (enviar/publicar) solo «autónomo»; `destructivo.ts` marca lo que publica para que siempre pida confirmación. Sin herramientas de borrar/descartar/forzar/fusionar PRs. Ver `docs/versiones.md`.
- **Inicio de sesión de GitHub con código (OAuth, flujo de dispositivo)**: `github/dispositivo.ts` (puro: `pedirCodigo`/`esperarToken`, maneja `authorization_pending`, `slow_down`, caducidad y cancelación) y `ServicioGitHub.dispositivoIniciar/Esperar/Cancelar`; el token acaba en el mismo `AlmacenToken` cifrado. Hace falta el **Client ID** de una OAuth App propia con «Device Flow» activado (`ODESK_GITHUB_CLIENT_ID` o `github-oauth.json`, que se guarda desde `components/GitHubOauth.tsx`); sin él solo está el token pegado. No hay secreto de cliente. Revocar: en GitHub → Settings → Applications. **Renovación**: si la OAuth App tiene «Expire user access tokens» (acceso de 8 h + `refresh_token` de 6 meses que rota en cada uso), `AlmacenToken` guarda el refresh cifrado y sus fechas; `ServicioGitHub.tokenVigente()` renueva 5 min antes de caducar o tras un 401 (`ClienteGitHub` repite la petición una vez), con una sola renovación en vuelo; un refresh inválido desconecta salvo que otro equipo ya haya dejado uno nuevo por la bóveda (que también lleva el refresh); sin red se sigue con el token actual. `ODESK_GITHUB_CLIENT_SECRET` solo si GitHub lo exigiera para renovar.
- **Sección «GitHub» (cuenta conectada)** (`components/GitHubCuenta.tsx`, entrada «GitHub» en Ajustes de la barra lateral): perfil (`/user`), cómo está conectada (`ServicioGitHub.cuenta`: método por prefijo del token —`metodoDeToken`—, permisos de la cabecera `x-oauth-scopes`, caducidad y refresh, límite `/rate_limit`; nunca el token), organizaciones, lo pendiente (búsqueda `/search/issues` con `@me`: mis PRs, revisiones pedidas, incidencias asignadas), tus repositorios (paginados de 100, filtros, cuáles ya están aquí por el remoto de cada carpeta —`reposLocales`, caché de 1 min—, clonar) y preferencias de clonado por equipo en `localStorage` (`github/preferencias.ts`: protocolo, carpeta, grupo; las usan `ModalClonar` y `ModalClonarPendientes`). Cambiar de cuenta / desconectar piden confirmación; el Client ID de OAuth se puede cambiar o quitar con la sesión abierta. `ConectarGitHub.tsx` (OAuth + token) lo comparten esta sección y Versiones → GitHub. El avatar sale de `avatars.githubusercontent.com` (permitido en la CSP de `index.html`; con otro servidor cae a la inicial).
- **Mis equipos** (`shared/equipos.ts`, `servidor/equipos.ts`, pestaña «Equipos» de Versiones, canal `equipos:operar`): cada escritorio sube a la API (`PUT /projects/:id/devices/:deviceId`, tabla `project_devices`) su rama, commit, adelante/atrás de su remoto (consulta el remoto cada 5 min) y cambios sin guardar; el id del equipo vive en `equipo.json`. Se informa en el bucle de `sincronizarCuenta` (30 s, solo si cambió o por latido). Sin rutas. Ver `situacionDe`. Además de rama/commit informa **qué cambió** (hasta 50 archivos con estado M/A/D/R/N/U y líneas +/−, `git diff --numstat`; **nunca contenido**), la **última actividad** (mtime más reciente de esos archivos) y la fecha del commit; con eso la interfaz marca «trabajando ahora» (archivo tocado hace <3 min) y `resumen` avisa (banner en Versiones y punto en el sidebar) de otros equipos con cambios sin guardar o commits sin enviar. Consulta barata: `estado('agrupado')` (sin archivos sin seguimiento uno a uno) y, si tarda >1 s, solo `ligero` y con espera (`lentos`/`noAntesDe`).
- **Clonar automático**: `proyectosSinCarpeta()` (proyectos de la cuenta con `repo` y sin ruta en `rutas.json`) alimenta la sección «En tu cuenta» del sidebar y `ModalClonarPendientes`; `ServicioGitHub.clonarProyecto` clona (el remoto guardado puede ser un alias SSH de otro equipo: `repoParaClonar` lo pasa a `propietario/repo`) y `vincularCarpetaAProyecto` lo deja enlazado al MISMO proyecto (no crea uno nuevo), tras lo cual se hidrata su contexto. Si el proyecto **ya está en este equipo** (otra carpeta, otro clon), «Ya la tengo aquí» del modal enlaza esa carpeta sin clonar: operación `enlazarPendiente` (`ServicioEquipos`) → `proyectos.ts#enlazarCarpetaExistente`, que no enlaza una carpeta que ya es otro proyecto aquí o está enlazada a otro proyecto vivo de la cuenta, y pide confirmación (`REQUIERE_CONFIRMACION`, con todos los avisos juntos) si trae el id de un proyecto que ya no existe en la cuenta o su remoto de git no es el del proyecto; si ya trae el MISMO id, es la carpeta correcta y se enlaza sin preguntar. **Cambiar carpeta** («Configurar proyectos», IPC `proyectos:cambiar-carpeta` → `proyectos.ts#cambiarCarpetaProyecto`) corrige un enlace equivocado: enlaza la nueva con esas mismas protecciones y `vinculo.ts#quitarVinculoLocal` borra el `.odesk/project.json` de la anterior solo si es de ese proyecto y no está versionado (si lo está, lo deja y avisa).
- **Historial local de versiones** (`src/main/historial/`, `src/shared/historial.ts` + `diff.ts`, pestaña «Historial local» de Versiones, botón «🕘 Historial» del editor, canal `historial:operar`): independiente de git y 100 % local. `AlmacenHistorial` guarda por proyecto (`~/.odesk-agent/historial/<id>/`) los contenidos comprimidos y deduplicados por sha256 (`objetos/`) y un `indice/<sha1 ruta>.jsonl` por archivo; `limpiar` conserva todo 30 días, luego una por día (90 d) y una por semana (365 d), siempre la última, y recorta lo más viejo al pasar 500 MB. **Todo entra por `ServicioHistorial.registrarRuta`** (una cola por proyecto, dedup por hash, ids monótonos): editor (`GestorArchivos`, origen *usuario*, con `antes`/`después`), IA (`Nucleo.registrarArchivoTocado` → `alEscribirIA`, origen *ia*: eventos `herramienta_inicio`/`fin` de las herramientas propias y de `claude -p`), `claude` en terminales ✦ (gancho `PreToolUse`/`PostToolUse` del plugin, `agentes.ts#configGanchosHistorial` → `mcp-tareas.js hook-historial` → socket de tareas, petición `__historial`) y `VigilanteProyecto` (un `fs.watch` por carpeta, sin `node_modules`/ocultas/generadas/`.gitignore`, tope de carpetas → vigilancia «limitada»; origen *externo*, o *git* si cambió `HEAD` o hay ≥25 archivos en 1,5 s). La primera vez que se ve un archivo versionado se guarda su `HEAD` de git como *base* (así el primer cambio ya tiene diff). `shared/diff.ts` es un Myers propio (agregadas/quitadas/modificadas, bloques con contexto, `aplicarBloques` para restaurar solo algunos). Restaurar guarda antes el estado actual (red de seguridad), escribe atómico y registra una versión *restauración*. Reglas (`reglas.ts`): solo texto ≤1 MB, sin secretos (`esArchivoSensible`), binarios ni lockfiles. Cada versión lleva usuario de GitHub, cuenta y equipo (`identidad` en `main/index.ts`): el mismo usuario en varios PCs, o varias personas en uno, se distinguen. Un resumen (solo nombres, nº de versiones y fecha, nunca contenido) viaja a «Mis equipos» (`project_devices.history`). Apagable por proyecto (`historial/ajustes.json`).
- **Duplicar pestañas y carrusel** (`renderer/duplicar.ts`, `components/TerminalGrid.tsx`, `App.tsx#sobrePestanas`): cada celda de proyecto tiene una barra de pestañas con la original de cada tipo (Terminal / Asistente / Archivos) y el botón «＋ Duplicar» añade **otra pestaña dentro de la misma celda**: hasta 3 duplicadas por tipo (4 por tipo, **12 pestañas máximo por celda**: `puedeDuplicar`). `TerminalInfo.extras` guarda las duplicadas (`PestanaExtra`: id `<celda>~<tipo><n>`, `n` = 2..4, `ptyId` solo en terminales) y `extraActiva` cuál se ve; `reducirPestanas` (puro) aplica agregar/cerrar/activar/pty. Cada terminal duplicada tiene su **propio pty** (sigue vivo aunque se vea otra pestaña; al cerrarla su proceso termina), cada asistente duplicado su **propia conversación** (clave `<proyecto>#<id>`) y cada panel de archivos su propio árbol y editor. Al **separar/devolver** una pestaña de la barra superior las duplicadas viajan con la celda (`aPayload`, `PayloadVentana.terminales[].extras`; en `ventanaDevolver` el principal debe reasignar también los ptys de `extras`, o cerrar la ventana separada los mataría). - **Estabilidad y registro técnico** (`main/registro.ts`, `shared/registro.ts`, `main/estabilidad.ts`, `renderer/vigilancia.ts`, `components/LimiteErrores.tsx`): `Registro` anota todo en `~/.odesk-agent/logs/app.log` (rotado a 2 MB) y lo sube por lotes a `POST /logs` (tabla `client_logs`; cola persistente en `logs/pendientes.json`, nunca bloquea ni lanza). `sanear` quita rutas personales, tokens y claves antes de guardar. `index.ts` registra `uncaughtException`/`unhandledRejection`, `render-process-gone` (recarga la ventana sola, máx. 3 en 1 min: `LimitadorRecargas`), `child-process-gone`, `unresponsive`/`responsive` (diálogo «Esperar/Recargar» a los 15 s), `did-fail-load` y el **cierre inesperado** de la sesión anterior (`logs/sesion.json` con `limpio`).
